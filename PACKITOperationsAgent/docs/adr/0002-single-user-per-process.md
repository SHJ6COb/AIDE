# Single-user-per-process, not a shared multi-tenant server

The MVP distribution model is: colleagues each open the shared project folder on their own machine and launch their own local instance via one CLI command — not one shared server multiple people connect to over the network. Given that, `app/core/harness.py` keeps conversation history as a single, per-process store (behind a small `ConversationStore` interface, not a bare global list) rather than building session-ID-keyed multi-tenant state — there is never more than one real user talking to a given process at once.

We considered designing for concurrent multi-user access from the start (matching the literal claude.ai/ChatGPT deployment shape — one server, many browser tabs). Rejected for the MVP: it would require session isolation, `splunk_client.py`'s currently-synchronous, already-live-verified search (`httpx.Client`, blocking up to `splunk_search_timeout_seconds`) to either become async or run behind a thread pool sized for concurrency, and none of that is exercised by the actual distribution model. The `ConversationStore` seam is kept precisely so this can be revisited without a rewrite if the project graduates past per-colleague local instances to one shared server later.
